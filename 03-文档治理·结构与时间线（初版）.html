一句话结论：他们没有把文档当"写作"来管，而是当代码来管——路径即元数据、每条事实只有一个家、字数有硬上限、一致性由 28 个 CI 门禁而不是人来守，中英文以 git blob 哈希绑定。文档量的爆炸并非失控，而是把 AI 代理每次改动必须"留下决策记录"这条规则机械化以后的必然结果。

一、现在的管理结构：五层 + 两条横切机制

把仓库里所有"有指引性"的 Markdown 按读者是谁、什么时候被读来分，可以拆成五层。每一层都有自己的 AGENTS.md（CLAUDE.md 只是指向它的符号链接），每一层文件的"能写什么/不能写什么"都在 docs/AGENTS.md 的分层表里被明确规定。

L1 指令层AGENTS.md ×8（另加 .agents/notes 下 3 份）· CLAUDE.md → 符号链接 ×4

每次会话都会被代理加载的"常备命令"。根 AGENTS.md 只写一到三行一条的规则并链到规则的家；子树版本（packages/、examples/、docs/、.agents/notes/、scripts/、website/、.github/、vendor/）只写该子树特有的命令。

字数硬上限：根 1,900 词（当前刚好 1,900）、docs/AGENTS.md 1,320、packages/AGENTS.md 675、examples/AGENTS.md 310——由 verify-doc-budgets 在 CI 强制。

L2 标准层docs/AGENTS.md · docs/i18n/README.md · .agents/notes/README.md

"规则的规则"：文档标准（分层表、写作规则、字数预算、slop 清单）、双语配对合同、Agent Note 的路径/格式/生命周期规范。三份文件合计不到 300 行，却是全部 16.9 万行的宪法；每一条规则都注明由哪个 verify-* 脚本执行。

L3 决策层.agents/notes/{proposed,implemented,rejected,archived}/{class}/日期-主题.md

Agent Notes——由代理写的 RFC。1,372 个 md 文件（含中文），占全仓 Markdown 行数的 45%。记录"为什么这样决定、放弃了什么、如何验证"，这些是代码和 README 装不下的东西。任何非平凡的 PR 必须新增或更新至少一条；生命周期由目录编码，格式由门禁校验。

L4 参考层docs/ (215 md) · packages/*/*/README.md (219/219)

人读的现状说明：architecture.md（有序总图，≤2,400 词）、subsystems/（92 个文件，每子系统一页，内嵌生成的 Cordis API 区块）、cookbook/（带编号验证步骤的 how-to）、postmortem/（唯一允许"讲故事"的层）、user/（网站发布的产品指南）、9 份由生成器写出的目录（tool/config/persistence catalog、module-graph、graph atlas 等）。219 个包全部有 README，且 README 必须含 ## Model Experience 与 ## Known Limitations and Deferred Work 两节。

L5 工作流层.agents/skills/*/SKILL.md ×11 · .claude/skills → 符号链接

可复用的操作程序，其中 6 个专管文档：dsh-doc-standards（放置与审计）、dsh-prose-standard（文风与覆盖）、dsh-trim-cot-leakage（清除思维链泄露）、dsh-archive-agent-notes（归档判定）、dsh-translate-docs（仅限用户手动调用）、dsh-doc-site-sync（网站投影）。规则的家在 docs，skill 只装流程——这条分工本身也被写进了 Agent Note。

两条横切整个树的机制：

  • 双语三元组。每份在范围内的文档是三个并列文件：foo.md + foo.zh.md + foo.i18n.yaml，第三个文件记录两侧上次被确认一致时的 git blob 哈希。任何一侧被改而未重新确认，verify-translation-pairing 就红。当前 1,078 组，中文侧 79,280 行——几乎恰好是全仓的一半。
  • 28 个 doc-sync 门禁。唯一一份叶子清单在 scripts/run-gates.ts 里，被本地 pnpm run doc-sync、CI 的 node 24 / static 任务和 GitHub Pages 部署工作流共用。

二、"一个事实只有一个家"：分层表

这是整套体系最核心的一张表，原文在 docs/AGENTS.md。每一层被规定了职责和明确不属于它的内容；重复出现的规则会被 slop 清单当作缺陷清掉。

层职责不属于这里
根 AGENTS.md常备命令：代理每次会话都需要在上下文里的规则，一到三行一条，链向其家故事、示例、情境流程、任何从链接目标复述来的内容
子树 AGENTS.md该子树特有的命令根文件已有的全仓规则
architecture.md有序总图：组合、核心包、循环、能力接缝、扩展点类型定义（→subsystems）、单包细节（→README）、决策理由（→Agent Notes）、实现状态标注
subsystems/每子系统一页：类型定义、语义、生成的 Cordis API行为叙述（→architecture.md）
Agent Notes活跃决策记录：为什么、放弃了什么、需要什么验证；implemented/ 用现在时描述已发布现实迁移计划、验收清单、"应当…"式规格语；归档笔记是冻结历史，不是现行权威
postmortem/事故故事——唯一允许叙事的层—
cookbook/带编号验证步骤的 how-to设计理由（→每篇链接的 Agent Note）
user/网站发布的产品指南生成参考表、贡献者流程、决策历史
包 README该包的合同：配置、语义、限制、扩展点、Model ExperienceJSDoc 复述、生成目录复述、别的包的事
生成参考从源码再生并做新鲜度校验的英文源；中文侧走配对流程手工编辑生成区块
Skills可复用工作流与专门的判定标准产品与运行时合同（→docs 或源码）

放置口诀（原文）：bug → postmortems；理由 → Agent Notes；流程 → cookbooks；类型定义 → subsystems；包合同 → READMEs；常备命令 → 根 AGENTS.md 并附理由链接。

三、Agent Notes 的生命周期与格式

路径就是元数据：{lifecycle}/{class}/yyyy-mm-dd-topic.md。日期是首次提出的日期，类别是封闭集合（scripts/agent-note-tree.ts），目录之外的任何位置都会被 verify-agent-note-classification 拒绝——连历史遗留的 docs/rfc/ 目录若重新出现也算失败。仓库明文禁止建集中式 INDEX.md：目录树本身就是索引。

格式由 verify-agent-note-format 强制：前三行必须是 # Agent Note: 标题 / 空行 / Status: …；## Alternatives considered 一节对所有笔记强制——"没有记录它击败了什么的决定，会招来重新争论"。2026-07-05 之前的旧笔记允许用一条固定注释代替。implemented/ 里若出现 ## Proposal、## Plan、## Acceptance criteria 即判失败。

两条防增殖规则：每篇新笔记必须触发取代检查（搜索活跃树里同一决定的旧笔记，全取代则合并后删除，部分取代则双向交叉链接）；归档不看字数与年龄，只看"替代方案、所有权边界、否定保证、持久/线上语义、安全规则、重新引入条件"是否仍有用。

pnpm run doc-sync = tsx scripts/run-gates.ts doc-sync，并行跑 28 个叶子（本地限 4 个 worker，因为几个门禁各自要建完整的 ts.Program）。按管什么可分六组：

字数预算：唯一有"松紧"的门禁

scripts/doc-budgets.manifest.json 是一张 9 行的路径→上限表。规则是双层的：manifest 里的上限是硬门禁；docs/AGENTS.md 里的目标更低（根 AGENTS.md ≤1,600、architecture ≤1,800、子树 ≤600）。低于目标时保留 ≥5% 余量，高于目标时冻结上限直到搬走或压缩内容。门禁变红的处置顺序：搬迁 → 压缩 → 提上限（须在 PR 里说明）。

本地钩子与 CI 的分工

lefthook 的 pre-commit 只做窄检查：暂存的 .i18n.yaml 配对、暂存的归档笔记封印、git diff --cached --check、第三方声明自动再生并重新暂存；pre-push 只跑 typecheck。全部 28 个门禁在 CI 的 node 24 / static 任务里对每个 PR 强制，Pages 部署工作流也先跑 doc-sync。原则写在 lefthook.yml 头部：本地检查点要快，CI 拥有完整矩阵。

六、可以带走的七条规律

  • 指令文件是"标准命令"，不是手册。根 AGENTS.md 每条规则一到三行、必须链到规则的家；峰值 51 KB 的教训直接催生了字数预算。今天它 1,900 词顶格，任何增补都要先付出搬迁或压缩的代价。
  • 规则一旦写成文字守不住，就把它写成脚本。从第 4 天的 doc-typecheck 到第 64 天的 28 个门禁，几乎每条写作规则后面都跟着一个 verify-*。团队自己的表述："值得保留的不变量就值得被编码。"
  • 路径即元数据，目录树即索引。Agent Note 的状态与类别全在路径里；INDEX.md 被明确删除，因为生成索引只会漂移。
  • 决策记录是 AI 开发的一等产物。"每个非平凡 PR 必须留一条 Agent Note"让 683 篇笔记成为最大的文档类别——它们记录的是模型下次进入时最需要而代码里没有的东西：为什么、放弃了什么、如何验证。
  • 增殖有配套的收缩机制。取代检查、合并删除、冻结归档（哈希封印、永不再编辑）三件套，让"必须写"不至于变成"越写越乱"。归档标准是价值判断，明文禁止按字数或年龄归档。
  • 双语不是翻译工程，而是一致性工程。三元组 + blob 哈希 + 结构签名匹配，把"中英文是否说同一件事"的可机检部分交给门禁，只把措辞是否准确留给评审。
  • 针对 AI 写作的专项反措施出现在最后。slop 清单（07-04）、prose standard（07-14）、CoT 泄露清除（08-09）依次出现，说明"AI 味"文档是在结构稳定后才成为主要矛盾。
